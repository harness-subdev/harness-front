# Web Component Motion Capture

실행 중인 웹 UI를 실제로 조작해 항목별 MP4와 대표 이미지(poster)를 만든다. 촬영 계획·실행 문맥·출처·항목 대응을 책임지고, 영상 변환은 기존 **web-video-optimize**를 재사용한다.

## 입력과 결과

대상 프로젝트/실행 URL, 실제 항목 ID 목록, 필요한 동작·반응형 상태, 카드 표시 규격, 출력 경로와 연결 범위를 확인한다. 기존 코드·설정에서 확인할 수 있는 값은 먼저 읽고, 결과를 결정하는 미확정 사항만 질문한다.

완료 결과는 항목별 영상/poster, 촬영·변환 기록, 기술·시각 검수 결과다. 카드 연결은 요청 범위에 있을 때 기존 연결 구조를 재사용한다. ID·개수·URL·포트·창 ID·DPR·크롭·길이·출력 크기·FPS·압축 설정은 모두 이번 프로젝트 값이다.

## 진행

1. **대상과 실행 문맥을 정한다.** 구현과 실제 호출처를 읽는다. 단독 렌더가 가능한 UI는 독립 화면을 쓰고, props/provider/children/스크롤 문맥이 필요하면 실제 소유 페이지에서 촬영한다. UI 없는 hook/provider는 실제 소비자의 반응으로 기록하고 `consumer-evidence`로 남긴다. 이를 독립 실행 성공으로 표시하지 않는다. 원본 소스·서브모듈은 촬영을 위해 수정하지 않는다.
2. **재현 가능한 샷을 만든다.** 항목마다 시작 URL/viewport, 스크롤·선택·저장 상태, 초기화 방법, 입력 순서, 기대 반응과 종료 조건을 정한다. 클릭·호버·메뉴·대화상자·필터·캐러셀·로딩 중 실제 필요한 장면만 포함한다. [촬영 기록 계약](references/capture-record.md)을 읽고 프로젝트의 기존 기록 형식에 맞춘다.
3. **촬영 경로를 확인한다.** 연결된 Chrome에 전용 탭을 만들거나 정확한 탭 ID/URL을 바인딩하고, 해당 탭의 입력·접근성·스크린샷과 연속 녹화 지원을 확인한다. 스크린샷만으로 연속 녹화가 된다고 간주하지 않는다. 창 녹화에서는 실제 창의 선택된 탭도 대상 URL인지 확인한다. 탭 이동·연결 복구 후에는 바인딩과 입력 대상을 갱신하고 짧은 입력 시험을 통과한 뒤 본 촬영한다. Playwright 스크립트·라이브러리·API를 사용하지 않는다. 다른 탭과 다른 채팅 작업을 방해하지 않는다.
4. **한 샘플로 경계를 검증한 뒤 촬영한다.** 현재 raw 픽셀 크기·웹 콘텐츠 경계를 직접 측정하고, viewport/DPR은 확인한 값만 기록한다. 창/배율/viewport가 바뀌면 다시 측정한다. 최종본에는 웹 콘텐츠만 남기며 탭·주소창·즐겨찾기·디버깅 표시줄·다른 앱뿐 아니라 도구가 덧그린 포인터 배지·하이라이트도 제외한다. OS 커서 숨김만으로 이를 충족했다고 판단하지 않는다. 대화상자가 닫힌 상태와 열린 상태를 모두 샘플로 검수하고, 오염이나 잘못된 입력이 섞이면 사용 가능한 구간을 확인하거나 재촬영한다.
5. **변환하고 출처를 남긴다.** [web-video-optimize](../web-video-optimize/SKILL.md)를 읽어 도구 확인·구도 보존·인코딩·실패 시 원본 보존 절차를 재사용한다. 이 작업에서 정한 구간만 trim/concat하고 실제 동작 속도는 유지한다. 필요한 내용을 자르는 대신 비율 유지와 padding을 선택한다. 최종 영상의 의미 있는 시점에서 poster를 만들고 원본→구간→크롭→출력의 대응을 기록한다. 무음 프리뷰인지 확인한 뒤 오디오 정책을 정한다.
6. **검수 후 연결한다.** 아래 완료 기준을 확인하고 성공한 파일만 반영한다. 제품의 조회·검색·필터에는 정적 에셋을 연결하며, 녹화·서버 실행·생성 API를 시작하는 경로를 추가하지 않는다. 원본 녹화와 임시 도구는 공개 배포 경로 밖에 보존하고, 기존 ignored 작업 경로가 있으면 재사용한다.

## 녹화 지원이 부족할 때

연속 녹화만 부족한 상태와 Chrome 탭 접근 실패를 구분한다. 지원되는 탭 작업과 샷 계획은 계속 진행한다. macOS 창 녹화가 필요하면 [macOS 창 녹화](references/macos-capture.md)의 권한 진단과 포인터 표시 제거 절차를 읽는다. 샌드박스 안의 권한 오류만으로 OS 미허용을 단정하지 않는다. 과거 작업의 승인은 현재 녹화 방식의 포괄 승인이 아니다. 필요한 승인이 없으면 정확한 대상·방식을 제시해 요청하고, 디스플레이 전체 캡처로 대체하지 않는다.

## 완료 기준

- **대응:** 입력의 전체 ID와 결과를 대조한다. ID 중복, MP4/poster 누락, 다른 항목의 영상 재사용을 검사한다. 미완료 항목은 누락/차단 이유로 남긴다.
- **기술:** 기존 프로젝트 검사나 ffprobe/ffmpeg로 이번 출력 계약의 코덱·픽셀 형식·크기·FPS·길이·오디오·faststart·poster를 확인한다. 샘플 프레임 변화는 정지 화면 탐지에 쓰되, 그 자체를 동작 의미의 증명으로 삼지 않는다.
- **시각:** 시작/동작/종료 장면을 실제로 보고, 필수 입력의 반응·내용 보존·웹 콘텐츠 전용 구도를 확인한다. 자동 검사만으로 시각 검수를 통과 처리하지 않는다.
- **제품:** 연결을 요청받았다면 실제 카드에서 항목 일치·재생·정지를 확인한다. 기존 가시성·탭 숨김·reduced-motion·사용자 pause·오류 시 poster 동작을 재사용한다. 브라우저 확인이 불가능하면 그 제한을 보고한다.

스냅샷이 오래된 영상 프레임을 보여주면 연결 도구가 현재 지원하는 다른 탭 스크린샷 경로와 실제 playhead/파일을 대조한다. 관찰 경로의 문제와 영상·ID 연결 문제를 구분하고, 근거 없이 캐시 우회 코드를 추가하지 않는다.

마지막에 처리/누락 개수, 에셋 경로·총바이트, 적용한 규격, 수행한 검수와 남은 제한을 짧게 보고한다.
