# v0.3.0

## 변경 내용

- 기존 Next.js 목표 앱도 React + Vite 포팅을 안내하도록 워크플로·구조·WebGL 분석 지침을 통일합니다.
- 지정 템플릿, TypeScript strict, Tailwind CSS, React Router, GSAP, `@gsap/react`를 목표 스택으로 기록합니다.
- 경로·서버 기능·인증·환경 변수의 대응, 별도 목적지와 초기·최종 검사를 포팅 절차에 포함합니다.
- 원본 Next.js Oracle과 분석 specimen은 비교 증거로 보존하며 목표 앱과 분리합니다.
- `source-port`와 `strict-clean-room` 경계를 명시하고 설계서 경로·승인 상태와 signature policy hash를 검증합니다.
- 카탈로그는 `react-vite`를 사용하며 `next` peer 의존성을 거부합니다.
- `role-first-portable-library` v2, InitPage, portable CSS와 두 TGZ 혼합 검증 계약을 포함합니다.
- 실제 실행 절차의 사전 조사·설계 순서를 검사하도록 lifecycle 테스트를 수정합니다.

## 설치 이름과 호환성

다음 스킬 이름을 변경합니다.

- `reconstruct-react-reference` → `web-reference-workflow`
- `design-system-reference-analyzer` → `web-reference-design-system-analysis`
- `interactive-webgl-analysis-poc` → `web-reference-webgl-poc`
- `site-reference-audit` → `web-reference-site-audit`
- `reference-design-document` → `web-reference-design-doc`
- `reference-project-readme` → `web-reference-readme`

총 아홉 스킬을 제공합니다. 이전 설치는 사용자 수정본을 백업하고 이전 이름을 탐색 경로 밖으로 옮긴 뒤 갱신하세요.
기존 `nextjs-react` 카탈로그는 새 Vite 목표의 현재 구현과 receipt로 다시 검증해야 합니다.
이전 schema-v2 signature receipt의 `architectureSha256`는 새 bindings 계약과 맞지 않습니다.
현재 승인 경로·signature policy와 캡처 조건을 확인하고 receipt와 후속 binding을 재생성하세요.
기존 hash나 승인 상태를 자동으로 유효하게 바꾸지 않습니다.

## 검증 범위

릴리스 빌드는 `bash scripts/build.sh`로 전체 Node 검사, graph regression, GLB·bundle 도구 검사를 실행합니다.
커밋한 소스를 압축하고 재해제한 스킬 파일·build-info·SHA-256을 대조합니다.
문서의 포팅 시나리오 검토는 실제 Next.js 앱 포팅이나 브라우저 패리티 검증을 대신하지 않습니다.
정확한 commit·build·run attempt는 아래 게시 메타데이터를 확인하세요.
